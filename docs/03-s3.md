# S3

- Two main concepts: **buckets** and **objects**. A bucket is a container; objects are what you store in it.
- **Bucket names are globally unique** — across every AWS account, not just yours. If someone anywhere already has `my-bucket`, you can't create it.
- Under the hood S3 is a **key-value store**: the key is a string (the object name), the value is binary data (the object content).
- **There is no hierarchy in S3.** No folders, no directories. A bucket is a flat list of keys, even when a key contains slashes.
- Slashes are a **convention** that creates an implicit hierarchy. Tools, including the S3 console, read `/` as a separator and show objects as files inside folders.

```
What S3 actually stores (flat):         What the console shows:

  photos/2024/cat.jpg                     photos/
  photos/2024/dog.jpg                     ├── 2024/
  photos/readme.txt                       │   ├── cat.jpg
  notes.txt                               │   └── dog.jpg
                                          └── readme.txt
                                          notes.txt
```

`photos/2024/cat.jpg` is one key. `photos/` and `photos/2024/` don't exist as objects of their own; they're just shared key prefixes.

## Public hosting and cost

With a public bucket, **the bucket owner pays for every download**, whoever makes it. Nothing caps it.

| Charge | Rough price (us-east-1) |
|---|---|
| Data transfer out to the internet | ~$0.09/GB, first 100 GB/month free (shared across all services) |
| GET requests | ~$0.0004 per 1,000 |

Storage is cheap; egress is what grows. A 1 MB image viewed 1M times is ~1 TB, so ~$90. A viral image, hotlinking by other sites, or a scripted download loop can reach thousands.

- **Requester Pays doesn't help.** It only bills signed-in AWS callers, and anonymous visitors aren't.
- **Failed requests are free.** Since 2024, AWS doesn't charge for 403s from outside your account. Successful public downloads still cost.
- **Budgets only send email**, on billing data that lags hours. They don't stop anything.

### Default: private bucket + CloudFront

There's almost no reason to make a bucket public directly. **Block Public Access** is on by default for new buckets (since April 2023), and the better pattern is:

```
viewer ──HTTPS──► CloudFront ──OAC──► S3 bucket (private)
```

- **Origin Access Control (OAC)** lets only your CloudFront distribution read the bucket.
- Transfer from S3 to CloudFront is free.
- CloudFront's always-free tier gives 1 TB out and 10M requests a month.
- **Flat-rate plans**, including a $0 one, have no overage charges. Past the limit, CloudFront throttles instead of billing. This is the real "stop serving when the budget is hit" switch that S3 lacks.
- You also get HTTPS on a custom domain. S3 website endpoints serve plain HTTP only.

Also compress images (WebP/AVIF, sensible sizes), since egress cost scales with bytes.

### Cloudflare instead of CloudFront

Cloudflare can't read a truly private bucket the way CloudFront does. OAC works because CloudFront is an AWS service that signs requests with an IAM identity. Cloudflare is outside AWS, so S3 has no built-in way to trust it.

| Option | How it works | Downside |
|---|---|---|
| IP allowlist | Bucket policy allows `s3:GetObject` only from Cloudflare's IP ranges (`aws:SourceIp`) | Every Cloudflare customer shares those IPs, so anyone can proxy your bucket through their own zone. You also have to keep the list current. |
| Secret header | Cloudflare adds a secret header (often `Referer`); the bucket policy requires it | Security by obscurity. S3 treats the bucket as public, so Block Public Access must be off. |
| Signing Worker | A Cloudflare Worker signs requests to S3 with SigV4 | Needs long-lived IAM access keys stored in Cloudflare, plus code to maintain. |

**Cloudflare doesn't cap the S3 bill.** Only S3 → CloudFront transfer is free. Each Cloudflare cache miss is a normal S3 download at ~$0.09/GB. Random query strings (`?x=123`) force misses unless the cache key ignores them.

**On Cloudflare, use R2 instead.** It's Cloudflare's S3-compatible storage with no download fees, served on your own domain without a bucket policy. Storage is ~$0.015/GB/month, with 10 GB free.

- Blog already on Cloudflare: use R2.
- Staying in AWS: use S3 + CloudFront + OAC.
- Avoid Cloudflare in front of S3. You lose the private bucket and still pay S3 for downloads.

### When a public bucket still makes sense

- **Public datasets**, often paired with Requester Pays for AWS callers.
- **Quick throwaway sharing.** Even here, a **presigned URL** on a private object is usually better: it expires and covers one object.
